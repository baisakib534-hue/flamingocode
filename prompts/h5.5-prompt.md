## What to build (exactly these)
(a) **Per-server trust** — each server gets `trust: 'trusted' | 'untrusted'`. New user-added servers default to `'untrusted'`. The 3 mandatory pre-installed MCPs (github, memory, fetch) default to `'trusted'`. Trust is shown in the server list and changeable in the server edit modal. Rule: a write-capable tool on an `untrusted` server must ASK the user before running — even in Off/YOLO mode — routed through the existing H2.3 `runApprovalLadder` (escalate path). The hardline blocklist still applies on top. Persist trust with the server (incl. A3 backup export/import).
(b) **Per-server tool picker** — each server gets an `enabledTools` list, edited with checkboxes in the server edit modal for the tools that server declares. Default on upgrade/creation: all declared tools enabled (no behaviour change for existing setups). Tools NOT enabled are hidden from the agent's context summary and must never be called. If a server declares no tools, the picker shows an empty state (no fake tools).
(c) **Per-server call/spend limit** — each server gets a `callLimit` (max tool calls per session, empty = unlimited) and a `spendLimit` field. Calls per server are counted in memory for the session. When the next call would pass the call limit, PROMPT the user (continue once / raise the limit / stop) instead of silently calling or silently blocking. The spend limit is stored, shown, and enforced through the same prompt path whenever a call reports a cost; when no cost is known the call limit governs.
(d) **MCP credentials never enter agent context** — audit the path that builds the MCP summary for the agent's system prompt (around line ~10044 and wherever the MCP summary is injected). Scrub credential fields (apiKey, token, password, secret, env secrets) from the server object BEFORE summarizing, so no credential value can ever appear in agent context. Add a regression test that puts a fake credential in a server config and asserts the summary contains no trace of it. (Real MCP subprocess env filtering is desktop-only — record that as a desktop note, do not fake it on web.)
(e) **Reload with confirm** — a Reload action in the registry that asks for confirmation before rebuilding the tool set (it invalidates the prompt cache), matching Hermes `/reload-mcp`.

Rules:
- Keep the diff surgical. One registry, one trust field, one picker, one limit mechanism — no second MCP system.
- A hardening failure (prompt declined, limit reached) must degrade gracefully: the tool call is blocked with a clear message, never a crash, never a silent skip.
- Bengali labels for the new UI (follow the existing i18n pattern).
- Commit in slices (every 2–3 slices, one commit per slice group, imperative messages).
