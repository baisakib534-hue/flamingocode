# DevForge — project rules for the builder

- Read `PRD.md` before every stage. Build ONLY the stage you were asked for, then stop and summarize.
- Stack: one self-contained page (vanilla JS/CSS), no frameworks, no build step. Lightweight is a feature.
- Use every installed skill — especially `no-ai-slop`, `senior-frontend`, `testing-qa`, `api-design`, `debugging-discipline`, `git-workflow`.
- Work like the dev team in the swarm protocol: plan → implement → self-review → test → fix → summarize.
- Commit after each stage with a specific message. Keep `git status` clean.
- Report honestly: what works, what is stubbed for the desktop version, and every known issue. Never claim a test passed that you did not run.
